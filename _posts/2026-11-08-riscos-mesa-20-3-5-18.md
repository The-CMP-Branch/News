Andrew Youll has released riscos-mesa 20.3.5-18, a new build of the software OpenGL port for RISC OS 5. Announced on the RISC OS Open forums on 4 November 2026, the port provides OpenGL 2.1, OpenGL ES 1.1 and 2.0, a native RISC OS EGL, SDL 2 with OpenGL, OpenAL and freeglut.

The development kit's SDL moves from 2.26 to 2.32.10, which Youll describes as the last SDL 2 release. That brings two years of upstream fixes and the functions added since 2.26 that newer games call. The RISC OS-specific parts of the driver continue to work as before.

SDL's relative mouse mode now works on RISC OS, so first-person games can use mouse look: the pointer is kept in the middle of the window and the game is told how far it moved. `SDL_WarpMouseInWindow` works too, for titles that move the pointer themselves.

Games can also tell when they have the keyboard. SDL now follows the desktop's input focus (the caret), so a program finds out when another window is clicked and when focus returns. Games that pause, mute or release the mouse on losing focus now do so. Previously, a game that waited for focus could wait indefinitely.

Until this release, UnixLib's semaphores did not really wait. `sem_wait` kept the waiting thread busy and leaked a little memory on every call, and `sem_timedwait` did not exist at all. SDL timers, game threads waiting on SDL semaphores, and OpenAL's background thread therefore used processor time spinning. UnixLib 5.0.3.6 fixes this, and 20.3.5-18 is built with it through riscos-crossdev 1.10. Waiting threads now sleep, which leaves more time for the game. Programs need relinking to pick the change up. SDL built against an older UnixLib still runs: it notices that `sem_timedwait` is missing and falls back to polling every millisecond.

OpenAL mixes with NEON on machines that have it, with the same sound as before. `*Set OpenAL$NoNEON 1` turns that path off.

2D games using the Pi overlay also copy less of the picture when updates are scattered. Each overlay buffer now keeps a list of up to eight changed rectangles instead of one box around them, so only those parts are copied.

Youll tested the release on a Raspberry Pi 4 running RISC OS 5.31 and separately on RISC OS on Linux. New host tests cover focus and the mouse, SDL semaphore waits, and OpenAL's NEON mixing. All the rendering tests still pass, on the host and on an emulated Cortex-A8, and rendering is the same as 20.3.5-17.

As with earlier builds, Youll notes that the code, build scripts, test programs and documentation were written with Anthropic's Claude as a coding assistant. UnixLib 5.0.3.6 comes from riscos-unixlib, an unofficial fork of GCCSDK's UnixLib, not made or supported by the GCCSDK developers.

The software needs RISC OS 5 on an ARMv7 machine with VFPv3, such as a Raspberry Pi 2, 3 or 4 or a Cortex-A8/A9 board, with SharedUnixLibrary and ARMEABISupport. The hardware overlay needs a Pi with the VideoOverlay module.

riscos-mesa 20.3.5-18 can be downloaded from the [GitHub releases page](https://github.com/adyoull/riscos-mesa/releases/tag/v20.3.5-18). Discussion is in the [forum announcement thread](https://www.riscosopen.org/forum/forums/1/topics/20561).
